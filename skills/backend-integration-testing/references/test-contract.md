# 用例编写与修改

优先复用项目已有测试框架。建议目录是 `tests/integration/`，已有 `src/test`、`integration-tests` 等结构时保留现状。

## 一条用例必须可执行

用例记录 ID、契约来源、前置条件/数据、操作、断言、截止时间、资源归属和清理。用例描述不是完成品；每项关键预期必须映射到自动断言。

- API：状态码、响应结构、关键值、授权边界及实际持久化效果。不能只断言 HTTP 200。
- 数据库：校验准确值、行数、唯一性、空值、事务提交/回滚；SQL 查询有稳定排序，差异在脚本里汇总。测试预期不得从被测结果直接复制生成。
- 异步/队列：通过返回的任务 ID/关联 ID 轮询终态，明确失败终态和截止时间；验证输出、消息或数据库副作用，不能只验证提交成功。
- 按风险补充：非法输入、重复请求/幂等、无权限、分页边界、并发冲突、依赖失败和恢复。只测本次需求相关行为。
- 测试真实后端与选定依赖的交互；替身适合无法接入的外部边界，但必须在结果标记覆盖缺口。

数据使用固定 seed 和 run_id/case_id 命名空间。SQL 文件拆成 seed/assert/cleanup 或复用迁移工具；回滚只适用于同一连接内且未由外部服务提交的数据。跨进程操作需显式清理或一次性数据库。

## 修改已有用例

先确定契约是否改变、测试是否缺陷、产品是否回归。保留稳定 ID 与仍有效的断言；改预期必须有需求依据，不能仅因为实际结果不同。测试设施修复与产品修复分别记录。

优先运行受影响用例及共用 fixture 的相关用例；只有共用环境/初始化改变或存在具体风险时扩大范围。并发运行必须隔离数据和资源，否则明确串行。

## Java 项目

保持项目实际 JDK、Maven/Gradle wrapper 和测试框架版本，不能为了测试随意升级 JDK。已有 Failsafe、JUnit、Testcontainers 时复用；不能因为引入本技能再强制换框架。

可通过 `./mvnw verify -Dit.test=...`（已配置 Failsafe 时）或已有 Gradle integrationTest 任务运行。Windows 使用项目的 `.cmd`/`.bat` wrapper 或显式 WSL；不要假设 Bash 存在。

多实例服务分别指定 profile、端口、日志目录、数据库/队列 namespace。进程存活不等于应用就绪；使用健康接口及必要的数据库迁移/任务执行探测。

## 简短执行报告

记录范围与版本、运行命令、run_id、PASS/FAIL/SKIP/BLOCKED 数量、首个失败的期望/实际、证据路径、清理结果及覆盖限制。诊断区分事实、假设和下一条验证命令；需要产品修复但未授权时，交付精简复现包给开发，不自动转入修改代码。
