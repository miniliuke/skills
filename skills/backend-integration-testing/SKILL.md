# 后端集成测试

把测试变成项目中的可重复执行资产。默认交付测试、执行证据和问题分析；只有用户明确要求修复业务代码或自动迭代时才修改产品代码。

## 调用与边界

- 仅接受用户手动点名调用。不得被默认开发流程、其他 skill、失败重试或模型自行路由触发。
- Codex 使用 `agents/openai.yaml` 的 `allow_implicit_invocation: false`；支持该字段的其他宿主使用 frontmatter 的 `disable-model-invocation: true`。宿主不支持策略时，将本技能放在其手动命令入口，不加入自动发现目录。
- 手动限制针对 **AI 调用 skill**，生成到项目的测试脚本可由人或 CI 重复执行，无需模型参与。
- 遵循项目已有运行器、测试目录和依赖管理；主要适配后端（Java/JDK 8+、其他语言均可），不绑定数据库对比或某种业务。

## 确定本次模式

按用户请求选择，可组合“编写/修改 + 执行”，不强制走完整流程。

| 模式 | 产出及边界 |
| --- | --- |
| 编写/修改 | 场景、可执行断言、数据与环境脚本、运行说明；修改时保留用例 ID 与有效断言 |
| 执行/诊断（默认） | 执行已有用例，收集日志，区分产品、测试、环境故障；允许修复测试设施，记录原因 |
| 自动迭代（显式可选） | 分析 → 最小产品修复 → 重跑失败用例及相关回归；默认最多 3 轮或用户指定预算 |

自动迭代中，每轮保存独立证据；相同错误连续两轮无新证据、环境阻塞或达到预算即停止并报告。不得削弱断言、跳过失败或无限重试来获得通过。

## 工作方法

1. **窄范围检查**：读项目约束、运行入口、已有集成测试及目标接口/异步任务的契约。确认本次范围、语言/运行时、依赖、启动方式和允许的测试目标。无需全仓审计或调用其他工作流。
2. **按行为设计用例**：记录稳定 ID、目标、前置数据、步骤、精确预期、超时与清理方式。按本次风险选正常、边界、异常和恢复场景；写入已有测试框架，不堆砌测试数量。编写或修改时读 [用例契约](references/test-contract.md)。
3. **持久化机械操作**：把配置、建库、数据准备、依赖安装、启动/等待、请求、SQL 校验、日志收集和清理写成 CLI/Python/SQL/Compose 等项目文件。重复执行不依赖聊天记录、临时路径或 AI 手动点击。新增依赖进入 lockfile/固定版本及项目虚拟环境。
4. **选择最小编排**：优先现有 pytest/JUnit/Failsafe/Make/Compose。缺少入口时可复制 `scripts/run_suite.py` 到项目测试目录，并按 [运行器接口](references/runner.md) 配置 `assets/suite.example.json`。这个运行器只是可选的顺序编排，不另建通用平台。
5. **管理环境**：读 [环境与日志](references/environment-and-logs.md)，支持容器、本地服务以及混合/多实例。明确资源归属、可用性探测、日志来源和失败清理。依赖不可用记为 BLOCKED，不把 mock 或跳过写成真实集成通过。
6. **执行并验证重复性**：按选择范围运行；新建/改变环境生命周期时，至少在清理后再运行一次，验证幂等和不依赖残留数据。只有文档调整无需启动全套环境。异步用有截止时间的状态轮询，业务断言默认不自动重试。
7. **先摘要，后局部日志**：先读退出码、结构化结果和失败摘要；再按 run_id、case_id、trace_id、时间窗口抽取上下文。用脚本计算 SQL 差异、计数、分组和统计，不让模型逐行处理大表或日志。
8. **交付可复现结果**：写清精确运行命令、目标/版本、通过/失败/跳过/阻塞数、证据位置、清理状态、已确认事实与待验证假设。没有执行就标为未执行，模拟验证与真实数据库/容器验证分别报告。

## 执行契约

- 项目内保留统一入口、用例、准备/校验/清理脚本、依赖版本和简短运行说明；日志、密钥和每次运行产物加入忽略规则。
- 支持按 case ID 或现有框架标签选测。单个用例应能从干净环境执行，不能要求“先在聊天里跑一条命令”。
- 编排表达依赖顺序：预检 → 依赖/服务启动 → 就绪 → 数据 → 用例步骤/断言 → 采集 → 清理。独立场景可继续执行；依赖失败的步骤标为阻塞。
- 输出机器可读结果（已有 JUnit XML/JSON 优先）及紧凑摘要，保存每阶段退出码、耗时、用例 ID、预期/实际和证据路径。采集/清理失败不能覆盖原始失败，也不能返回虚假成功。
- 环境脚本只能清理由本测试创建并记录的资源。默认隔离测试库、容器、网络、卷和临时文件；不对共享环境执行全局 prune、删库或按端口杀进程。
- 模型用于场景设计、少量证据判断和必要的分支选择。凡能确定执行的循环、等待、环境操作和断言交给脚本；AI 决定的可复用分支回写到项目脚本，不把模型接入设成每次测试的必需依赖。
